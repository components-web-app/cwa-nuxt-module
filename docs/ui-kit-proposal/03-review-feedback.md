# Part 1. Raw reviews

## dev-site: approve-with-changes

**Must fix**
- **DS-M1** §8.6 rests on a false assumption, and it is a visitor-path break. `getCurrentStyleName` is part of `useCwaComponent`'s public return (src/runtime/composables/cwa-component.ts:28-43). SR calls it in visitor templates to switch markup by style name: /Users/danielwest/Documents/GitHub/srnte/app/app/cwa/components/NavigationLink/NavigationLink.vue:32 and TextBlock/TextBlock.vue:48. If `styles` moves into the admin-only `cwa-admin-config.ts`, it returns undefined for visitors. Fix: keep the class map available at runtime. Have the macro transform pass `styles` into the component's `useCwaComponent` call, so it stays in the component's own chunk, which costs nothing compared with today. Move only `description`, `defaultData` and `fields` to the admin template. Replace the 'to verify' note with this finding.
- **DS-M2** `defineCwaConfig` is not scanned in `ui/*.vue` variants, but today styles and names belong to each variant. `Ui.vue` reads `current.styles` from the rendered instance's `exposeMeta` (Ui.vue:50-51), and it takes each variant's label from `meta.cwaResource.name` by mounting every variant through `useDataResolver` (Ui.vue:39-44). The playground has variants (HtmlContent/ui/AltHtmlContent.vue, UiComponent/ui/JournalPageLayout.vue). The draft only reads `<Name>/<Name>.vue`, layouts and pages, so a variant's own styles and name have nowhere to go. Allow `defineCwaConfig({ name, description, styles })` in `ui/*.vue`, keyed by variant. Have the Ui tab read names and styles from the generated config instead of mounting every variant. That is also a DX and performance win.
- **DS-M3** §4.4 promises that the link input 'clears the other field in the same PATCH', but the API it shows cannot do that. In 5.2, `route` and `rawPath` are two separate `useCwaResourceModel` instances, and each debounces and PATCHes on its own: `rawPath` waits 250 ms while `route` waits 0. That gives two requests, a transient state where both fields are set (or neither), and an API either/or validator that can 422 between them. The developer also has to remember `{ debounceTime: 0 }` on `route`, which the component cannot set on a model it receives. Fix: give `CwaUiLinkInput` ownership of its models, e.g. `<CwaUiLinkInput :iri="iri" label="Link" />` with optional `route`/`raw-path` field names, backed by a model that writes both keys in one merge-patch. Or state plainly that this is two PATCHes and order them so 'clear' goes first.
- **DS-M4** The single-row rule is easy to break by omission, because the fallback is the dangerous value. A field with no surface 'falls back to `page`' (§3), which puts the label above it. So a tab author who forgets `<CwaUiManagerRow>` (today's tabs root in a `<div class="flex">`; see playground NavigationLink/admin/LinkTab.vue and CollectionTab.vue) gets stacked labels in the bar. Fix: have the bar frame (`ResourceManager.vue`) provide the `bar` surface and wrap every tab in a row itself, so the row is the default rather than opt-in. Also, §5.5's claim that the row stops wrapping is only true for direct children. `<CwaUiManagerRow><div class="cwa:flex cwa:flex-col">…` still stacks, and the fixed-height `overflow-y` clip then hides the second line silently. Add a dev-mode check, for example a ResizeObserver on the row's content that warns when its height exceeds the control height, naming the tab.
- **DS-M5** Selects from an API collection have no component API. Field declarations (§8.8) give `select`/`multiselect` an `endpoint + property` source, but `CwaUiSelect`/`CwaUiMultiSelect` in §4.3 take only static `options`. A hand-written tab can therefore not do what a generated tab can, and the generated tab would need an unspecified internal path. That hits a common case: the Collection tab's resource/category picker, and CK categories. Give the components themselves an `endpoint`/`property` (prefix-free) options source, with loading and error states in the status slot. Have `CwaGeneratedTab` use exactly that.
- **DS-M6** `CwaResourceUploadBind` does not have what §4.5 renders. Today it is `{ modelValue, fileExists, disabled, onChange, onDelete }` (src/runtime/composables/cwa-resource-upload.ts:15-22): no thumbnail URL, filename, size, progress phase, error/retry, presence or conflict. 'bind already exists and becomes the only input' therefore hides a composable redesign. Specify the new bind shape and say how an upload takes part in presence and focus (it is not a `ResourceModelField`), or the 'every `:model` control shows presence, including uploaders' requirement is unmet. Also align the prop names: `CwaUiFileUpload :bind` vs `CwaUiImageAlt :upload`.
- **DS-M7** The D2 warning fights its own reason. The precedence 'nuxt.config.ts overrides so an app can still patch a layer's component' is right, but 'a key set in both warns at build time' means every intentional layer patch warns on every build, so developers learn to ignore the warning. Warn only when both definitions come from the same layer or rootDir, and treat an override from a higher layer as a documented, silent patch.

**Suggestions**
- **DS-S1** Cut the per-field boilerplate. Even with the kit, a 7-control tab is 7 typed `useCwaResourceModel(iri, '…')` lines plus `useCwaResourceManagerTab` plus `defineExpose(exposeMeta)` (§5.3). Inside a manager tab the iri is already known: add a `field="heading"` shorthand on kit inputs that creates the model from the tab's injected iri. Keep `:model` for anything custom (page data, options such as debounce). Its consumer is the 153 title/label tabs. SR's NavigationLink `LinkLabel.vue` would shrink to a 3-line template.
- **DS-S2** `:model` and `v-model` differ by one character, and `v-model="title"` (passing the whole model object) is an easy, silent mistake. In dev, warn when `modelValue` is an object with `model`/`remoteChange` keys. Better still, rename the prop to `:field` so it cannot be confused with Vue's model.
- **DS-S3** Derive `target` instead of trusting it. Compare the model's IRI type (`getResourceTypeFromIri`) and identity with the selected stack IRI, and draw the page or page-data badge automatically. As a hand-set prop it can be missing or wrong, and the brief says that case occurs in at least two sites.
- **DS-S4** Say how `managerTabs` names resolve in `defineCwaConfig`. The example uses the short `'LinkTab'`, but today's entries are global pascal component names from the `admin/` scan (module.ts:303-327). Define them as file basenames relative to `admin/`, and make the generated `CwaManagerTabName` union per component, so one component's tabs do not autocomplete in another's config.
- **DS-S5** Q-D: allow imports, but only from files that do not use `#imports`/`#cwa`/Nuxt aliases, with a build error naming the file. Otherwise evaluating a site's constants module at build time fails on its auto-imports with an opaque error. Shared option lists between the config and custom tabs (5980bc variants/tones, dons-hub LINK_CARD_ICONS) are the main DX payoff, so do not drop them for literal-only.
- **DS-S6** Show in §8 that the macro transform also runs under sites' `vitest-environment-nuxt` and `nuxi typecheck`. Without the transform, a component spec hits a ReferenceError in an untouched visitor component. Consider a dev/test-only runtime stub that throws with a clear message rather than a bare ReferenceError.
- **DS-S7** Add `useCwaSelect` to the §9 migration table. CollectionTab.vue uses it, including the `unshift({ label: 'Please select', value: undefined })` hack, which `nullable`/`placeholder` replace. Rename `CwaUiImageSlots`' `slots` prop (e.g. `items`), because `slots` is easily confused with Vue slots in templates and docs.
- **DS-S8** Worked rewrite for the doc: SR NavigationLink today has `LinkLabel.vue` + `LinkTab.vue` (two tabs, ~55 lines, `v-model="x.model.value"`, so no presence or conflict). With field declarations it becomes `managerTabs: [{ name: 'Link', fields: [{ name: 'label', kind: 'text', label: 'Label' }, { kind: 'link', label: 'Link' }] }]` and the two tab files are deleted. Add this before/after to §8.9. It shows the D3 payoff better than the abstract table and argues for shipping 6b sooner.
- **DS-S9** A held conflict on an unmounted tab (Q-A): recommend `KeepAlive` for a tab with a held save rather than an implicit Keep mine. Silently picking mine on a tab switch is the same silent-resolution class of bug the brief is trying to remove.

**Praise**
- **DS-P1** Surfaces provided by inject, with no `labelPlacement` prop, is the right structural enforcement of R1. The textarea dev-throw under `bar` is the same idea applied to the second-most-common violation.
- **DS-P2** The flag-lane finding (`overflow-x: auto` forces vertical clipping, so `bottom-full` presence flags would vanish in a scroller) is a real trap that would otherwise have shipped broken. Reserving it in the height token is the right fix.
- **DS-P3** The always-reserved 16 px status slot as its own tiny component reading only that field's refs gives saving, saved, error and conflict without layout shift or tab re-renders, and it maps directly to §7.7.
- **DS-P4** Spotting that `cwa-options.ts` is imported by `plugin.ts`, and therefore in every visitor entry, before adding admin-only keys to it is exactly the bundle discipline CLAUDE.md asks for. The direction is right, even though `styles` specifically must stay at runtime.
- **DS-P5** Precedence designed key by key, with explicit `managerTabs` rules (unlisted scanned tabs are appended with a warning, unknown names are errors), means a tab never silently disappears. The module.spec case list is concrete.
- **DS-P6** `CwaUiNumber` committing on blur, Enter or step, so the model's debounce sees one change, fixes `Order.vue`'s per-keystroke emits without touching save semantics.
- **DS-P7** The §5 examples read well: 5.1 is genuinely four lines of logic, and binding with `:model` once to get presence, conflict and save state makes the correct path the easy one.

## dev-module: approve-with-changes

**Must fix**
- **DM-M1** §8.6: moving `styles` out of the runtime would break visitors' pages. Its 'to verify' assumption is false. `getCurrentStyleName` is part of `useCwaComponent`'s public return (cwa-resource.ts:82-85), and sites read it while rendering for visitors: srnte `NavigationLink.vue:32` and dons-hub `HtmlContent.vue:53` (`isHero`). Moving `styles` into the admin-only `cwa-admin-config.ts` would make these return undefined. Either keep each component's class map in its own chunk (have the macro compile `styles` into a const the component closes over) or design a replacement read before going further.
- **DM-M2** §8.3/§8.4: `styles` belong to a UI variant, not to the resource. CK's `Image/ui/PortfolioImage.vue` and `CaseStudyImage/ui/CaseStudyImageColumn.vue` declare their own `styles`, and the base `Image.vue` declares none. Ui.vue reads `styles` from the mounted instance's `exposeMeta`, so today it shows the active variant's styles. The draft scans only `<Name>/<Name>.vue` and stores `styles` per resource, so variant styles would be lost. Allow `defineCwaConfig({ styles })` (styles only) in `ui/*.vue`, key the generated styles by variant, and have the Ui tab choose the active variant's styles.
- **DM-M3** §8.6: splitting `description` and `defaultData` into a lazy `cwa-admin-config.ts` breaks the synchronous `$cwa.resourcesConfig` API. Five admin consumers read it synchronously: AddComponentDialog (`defaultData` at line 200), DataPage, PresenceIndicator, ClonePlacementMenu and ManageableResource. The values from `nuxt.config.ts` are serialised into the entry today, and the draft does not say whether they move too. If they do not, there are two sources for one key. Specify one async accessor, state that `nuxt.config` values for these keys move as well, and record the `resourcesConfig` shape change in the changelog and migration notes.
- **DM-M4** §8.3 regeneration will reload the dev page on every save. Today `cwa-options.ts` is regenerated only on add and unlink. Re-reading the config on every `.vue` change and rewriting `cwa-options.ts`, which `plugin.ts` imports, forces a full reload on every component save in dev. Hash the extracted config per file and call `updateTemplates` only when the hash changes, and have a test that a template-only edit does not regenerate.
- **DM-M5** §8.3 'fails loudly': a `defineCwaConfig` call that the transform misses becomes a runtime ReferenceError in a visitor's render, which means a 500 in production. Make it a build error instead: the transform `enforce: 'pre'` throws whenever it finds a call it cannot statically strip. Do not rely on the missing runtime export.
- **DM-M6** §8.4 `managerTabs` names do not match today's shape. Scanned tabs are `GlobalComponentNames` (full pascal names from `resolveComponentNames`), and `ManagerTab` also accepts a `DefineComponent` from `nuxt.config`. The draft's short `'LinkTab'` needs a defined mapping to the full name, and Q-E has to say how a component object in `nuxt.config` interacts with the config's order.
- **DM-M7** §7.2 network loss rests on a mechanism that does not exist. `useCwaResourceModel` has no `online` path. A failed save leaves the local value with `pendingSubmit` false, so the field is in error, not pending. Resending on `online` would be a new save behaviour, which the brief rules out as a non-goal. Either drop the claim or list it as a model change next to D5.
- **DM-M8** D5 understates the work. Errors are recorded in the error store and cleared with `removeByEndpoint`, which is the cross-field clearing bug, and `updateResource` does not raise errors to the model. Per-field `states.error` therefore also changes the error store, or the model derives it from store entries filtered by its `source` (already on the event). Say which, and make `retry()` call `updateResource(localValue, true)`.
- **DM-M9** §4.4 'clears the other field in the same PATCH' cannot be done through two `useCwaResourceModel`s. Each one sends its own debounced, versioned PATCH, so this would bypass the model, against the 'renders, does not redesign' non-goal. Choose one: two PATCHes in sequence (the If-Match queue already orders them), or one direct `resourcesManager.updateResource` with both fields. The pick-saves-at-once behaviour also depends on the tab author passing `debounceTime: 0` (§5.2). Have `LinkInput` take `iri` and the two field names and create its own models, so authors cannot get this wrong.
- **DM-M10** §10 contrast: `line` #44403c on `surface` #1c1917 is about 1.6:1. A dotted outline at rest is the only boundary of an empty input, so WCAG 1.4.11 needs 3:1. Lighten the resting outline or add a contrasting fill, and remove the 'only where it is the only boundary' hedge.
- **DM-M11** The auth light field (§5 SHOULD) is missing. The draft never carries over the #386 autofill read in the directive's `created` hook. Auth and `/_cwa` pages render on the server, so field ids and `aria-describedby` must come from Vue's `useId()`, not a counter, or hydration will not match. State both.

**Suggestions**
- **DM-S1** Q-D: ship literal-only for `defineCwaConfig`. Evaluating app modules at build time with jiti breaks as soon as a constants file imports `#imports` or vue. Add imported constants later if a site needs them.
- **DM-S2** Do not reserve `fields` in the `CwaTemplateConfig` type now (§0 D3, §8.2). An unused key fails R7. Keep the 6b design in the doc only.
- **DM-S3** Leave `styles.multiple` out for layouts and pages. Page, layout and data modals offer one choice (Default plus options), so `multiple` has no consumer there. Layout and page `description` has no consumer either: name one (for example the template select in `PageAdminModal`) or drop it.
- **DM-S4** §8.4: when `nuxt.config` deliberately overrides a component that comes from a layer, the both-set warning is noise on every build, and the draft itself says patching a layer's component is why `nuxt.config` wins. Warn only when both sources sit in the same layer, or at info level when they do not.
- **DM-S5** `cwaIri`: resolve the marker in its one consumer, the AddComponentDialog `defaultData` merge before `setAddResourceEventResource`, not 'in ResourcesManager when created'. Use `ResourceTypeFromIri`'s prefix, which is already set per request, rather than calling `resolveApiUrl` again.
- **DM-S6** Q-A: deselecting the component unmounts its models as well as switching tabs does, and `onBeforeUnmount` unregisters the editor, so a held conflict disappears silently either way. `KeepAlive` on tabs fixes only half. Raise the conflict to the model-editor registry (keyed by `$cwa`), so the tab badge and the header can show it after unmount, or decide that unmounting resolves it as Keep mine and say so.
- **DM-S7** §2.2: redefining `text-sm` as 13/20 silently resizes 117 existing `cwa:text-sm` uses. Add new names (`text-control`, `text-label`) instead of overriding Tailwind's scale.
- **DM-S8** §2.1: blue-400, blue-700, amber-700, lime-800 and red-700 are not in the admin palette (R5 says palette only). Ask Daniel to approve them explicitly. Declare the light scope with `@utility theme-light` so the prefix is applied by Tailwind, not written by hand. `surface-sunken` is missing from the `@theme` block, and the light override has no `accent`.
- **DM-S9** §2.3: the 100 px bar spends a fixed 20 px flag lane on every tab, though the flag is rare. Compare it with today's height. Consider portalling the flag into a lane at bar level outside the scroller (the row already portals popovers), which would let the row stay about 44 to 48 px. Also, `overflow-x: auto` makes `overflow-y` compute to `auto`, not `clip`, so a stray vertical scrollbar can appear: set `overflow-y: hidden` explicitly.
- **DM-S10** §4.9: the inline conflict control widens the field and pushes later fields sideways in the row, which goes against principle 2. Either say horizontal shift is acceptable, or anchor the conflict to the status slot as an always-open popover.
- **DM-S11** §4.2 announcements: announcing 'Saving title' and 'Title saved' on every debounce floods screen readers. Announce errors, conflicts and saves that recover from an error, and leave routine saves out.
- **DM-S12** §4.6: drop the vertical-wheel-to-horizontal remap. 'The page is not being scrolled' cannot be detected reliably, and Shift+wheel and trackpads already work. The draft offers two names, `CwaUiManagerRow.Divider` and `CwaUiRowDivider`: dot notation does not auto-import, so keep only `CwaUiRowDivider`.
- **DM-S13** §7.1: the toaster can be a lazy admin component that watches the error store, which is what `RequestErrors` does today. Then `ResourcesManager` in the entry never calls `useCwaToast`, and the WeakMap can be keyed by `vueApp`, as `createConfirmDialog` is, instead of `nuxtApp`. Do not mount it with `createApp` and a lazy component (CLAUDE.md trap).
- **DM-S14** Testability: `CwaUiManagerRow`'s fades depend on `scrollWidth` and ResizeObserver, which are 0 or missing in happy-dom. Inject the measurement so Vitest can drive `data-overflow-*`, and leave real overflow to the browser scenario.
- **DM-S15** Phase the new kit surface so each reka-ui consumer's chunk cost is measured once: Dialog, Toast, NumberField, ToggleGroup, Combobox, Pagination and Tabs are each a possible `__vite__mapDeps` split. List the expected budget moves per step of §12.

**Praise**
- **DM-P1** It sets the label from the surface through inject instead of a `labelPlacement` prop. That enforces R1 by structure rather than by documentation.
- **DM-P2** It reserves a status slot of fixed width per field, and the status component reads only that field's refs. That is the right answer to the brief's 60 fps and no-layout-shift requirements.
- **DM-P3** It caught that `plugin.ts` imports `cwa-options.ts`, so anything added there reaches every visitor's entry. Splitting admin-only keys into a lazy template is the right instinct; it needs the fixes listed above.
- **DM-P4** Choosing a compiler macro, parsed with the SFC parser already used for group declarations, meets the user's 'one place' request at a parsing cost the module already pays. The keys, types and precedence are kept independent of the D1 choice.
- **DM-P5** It names real gaps: the silent hold on `CwaUiSelect` with `:model`, the stale CK and SR date pickers, the fact that vertical clipping in a horizontal scroller would hide today's presence flag, and Q-A's tab-unmount hole.
- **DM-P6** Every component names its consumer, and the migration table covers every existing public `CwaUi*` name.

## dev-types: approve-with-changes

**Must fix**
- **DT-M1** §8.6 moves `styles` into an admin-only `cwa-admin-config.ts` and deletes the runtime `useCwaComponent(…, { styles })` option, which breaks a public API. `useCwaComponent` returns `getCurrentStyleName` (src/runtime/composables/cwa-component.ts:28-43). It is computed from `ops.styles.classes` (cwa-resource.ts:82-85) and apps can call it in visitor templates to branch rendering. In the §8.1 example, `useCwaComponent(props)` gets no styles, so `getCurrentStyleName` silently returns `undefined`. `ComponentPosition.vue:70` also reads `component.cwaResource?.styles` through `exposeMeta`. The macro transform must therefore inject `styles` back into that component's own `useCwaResource` ops at compile time; it costs no more than today, because the class map already ships in that chunk. Only `description`, `defaultData` and `fields` should move to the admin-only template. Resolve the 'to verify' item as 'verified: it is read on the visitor path'.
- **DT-M2** The `managerTabs` and `ui` names in `defineCwaConfig` do not match what the module stores today. `extendCwaOptions` collects full `GlobalComponentNames` pascal names (`CwaComponentNavigationLinkAdminLinkTab`-style, module.ts:303-318), and the `ManagerTab` type also allows a `DefineComponent` object (types/index.ts:9). The draft writes short names (`'LinkTab'`, `'NavigationLinkButton'`). Pick one. Short names, the file basename under `admin/`/`ui/`, are better DX, but then the draft must say how they map to the global name, and that `nuxt.config.ts` keeps accepting full names and component objects. Otherwise §8.4's 'a name not in admin/ is a build error' is not checkable.
- **DT-M3** `CwaManagerTabName` and `CwaUiName` are generated as single global unions, so `defineCwaConfig` in NavigationLink.vue would type-check a tab that belongs to another component. That does not meet the brief's 'typed against CwaComponentNames'. Generate a per-component map (`CwaComponentConfigMap['NavigationLink']['tabs']`) and either key the global overload by component name (`defineCwaConfig<'NavigationLink'>({...})`), or have the transform emit a per-file `declare` so the call is narrowed by its file. The same applies to `ui`.
- **DT-M4** Keep one config type instead of adding a parallel `CwaTemplateConfig`. `CwaResourceMeta` (types/index.ts:13) for `nuxt.config.ts` should become the single type, extended with `styles` and later `fields`, and used by both `defineCwaConfig` and `cwa.resources.<Name>`. Without that, `styles` cannot be overridden from `nuxt.config.ts`, which undercuts the user's 'define what we would in the nuxt config' and D2's key-by-key precedence. In the same way, `CwaUiMeta.classes` for layouts and pages must move to `styles.classes` in both sources at once, with a changelog line, and it gains `description`. Also rename one of the two exported `CwaResourceMeta` interfaces: types/index.ts and composables/cwa-resource.ts both export one, with different shapes.
- **DT-M5** `name` has a third source the draft ignores: `useCwaComponent(props, { name })` / `CwaResourceUtilsOps.name` flows into `exposeMeta.cwaResource.name`. State its precedence against `defineCwaConfig.name` and the nuxt.config `name`, or deprecate it alongside the runtime `styles` option.
- **DT-M6** The surface fallback is in the wrong place. A field outside any surface falls back to `page` (label above), so a tab author who leaves out `<CwaUiManagerRow>` gets labels above fields in the bar. That breaks R1, the very mistake the kit is meant to make impossible. The bar frame in `ResourceManager.vue` should provide the `bar` surface for everything mounted in a tab. `CwaUiManagerRow` then only adds the row layout, and a field that is in the bar but not in a row should warn in development.
- **DT-M7** D5 contradicts §4.2 and §7.2. The model gains `states.saved`, 'a short-lived flag', while the shell also runs 'one setTimeout per field' for the 1.5 s tick. Presentation timing does not belong in a data composable that headless tabs and generated tabs also use. The model should expose a fact (a `savedAt`/`lastSavedAt` counter, or a `lastResult` ref) and the status slot should own the 1.5 s timer. The saving indicator should read the existing `states.isBusy` instead of re-deriving `pendingSubmit || submitting`.
- **DT-M8** Make the tone vocabulary one union. Today it is Toast `kind: success|info|warning|error`, Alert `tone: info|success|warning|danger`, StatusText `tone: neutral|success|warning|danger`, Badge `tone: neutral|accent|success|warning|danger`, and Button `color: …|danger`. Pick `tone` everywhere, use `danger` everywhere, and define one exported `CwaUiTone` type that each component narrows with `Extract`.
- **DT-M9** `size` is overloaded and collides with the Nuxt UI convention the brief says to drop. On fields it means width (`xs`-`lg`, `auto`); on `CwaUiDialog` it means dialog size; Nuxt UI's `size` means control scale. Rename the field prop to `width`, so ported code and the 'no size theming' rule don't fight it. Also give the shared `CwaUiFieldProps` only the props every control honours: `placeholder` means nothing on Toggle, Segmented or FileUpload.
- **DT-M10** Compound controls break the 'every input takes the 4.2 props' contract without saying so. `CwaUiLinkInput` takes `route`/`rawPath`, `CwaUiImageAlt` takes `upload` + `alt`, `CwaUiFileUpload` takes `bind`, `CwaUiImageSlots` takes `slots[].bind`, and `label` is optional on these though required on `CwaUiFieldProps`. Define a separate documented contract for multi-model controls (which model drives the status slot, presence and the live-region name), make `label` required everywhere, and use one prop name for an upload binding (`upload` on all three).

**Suggestions**
- **DT-S1** Generics for select options: write `CwaUiSelect`, `CwaUiMultiSelect`, `CwaUiSegmented` and `CwaUiSwatchSelect` as `<script setup generic="T">`, with `SelectOption<T> = { label; value: T; description?; disabled?; reason?; group? }`, `model?: ResourceModelField<T>` (MultiSelect: `ResourceModelField<T[]>`) and `modelValue?: T`. Give them a `by?: keyof T | ((a: T, b: T) => boolean)` prop instead of today's hard-coded lodash `isEqual` in `useCwaSelectInput`. Today `SelectOption.value` is an untyped union (`ModelValue`), so `:options` and `:model` are never checked against each other. Check generic SFC declarations against the TS2883 empty-.d.ts trap in `check-declarations.mjs` early.
- **DT-S2** Both binding paths: state what happens when `:model` and `v-model` are both passed (Input.vue today lets the field win silently; warn in development). State that a `:model` control never emits `update:modelValue`, so a site can't double-write.
- **DT-S3** Commit semantics differ between controls. `CwaUiNumber` and `CwaUiInlineEdit` commit on blur or Enter, but under `v-model` the draft doesn't say whether `update:modelValue` fires per keystroke or on commit. Make it commit-only for those two, add an explicit `commit` event, and document the difference from `CwaUiInput`.
- **DT-S4** `nullable` has three meanings: Input maps `''` to `null`; Select adds a 'None' row and also has `clearable`; Segmented adds an 'Unset' segment. **Must fix**

ResourceManager.vue renders only the selected tab (`<component :is="selectedTab">`). useCwaResourceModel keeps `heldChange`, `pendingSubmit`, `isLongWait` and the proposed `states.error`/`saved` as local refs, and its onBeforeUnmount drops them. The draft must say that the Ui tab and `getCurrentStyleName` will read styles by component name from cwa-admin-config.ts, and how that works for layouts and pages, which do not go through useCwaComponent. WCAG 1.4.11 needs 3:1, and §10's claim that outlines 'meet 3:1 where they are the only boundary' contradicts the token table. Either use `line-strong` (6.9:1 dark, 4.8:1 light #78716c) for input boundaries and keep `line` for dividers only, or give controls a fill that is distinct at 3:1.
- **UT-M2** The contrast figures in §2.1 are wrong and hide two failures. Blue-600 on stone-900 is 3.38:1, not 2.9:1. It is 2.93:1 on surface-raised, which fails 3:1 for a selected tab or a toggle track inside a popover or menu. `danger` #ef4444 is 4.65:1 on surface but 4.03:1 on surface-raised, so red error text in the error popover or a toast fails AA. Add a `danger-fg` (red-400 range) for text, and recompute every pair against surface-raised and the 85% blurred `surface-sunken` over a white site page, not only against pure stone-900.
- **UT-M3** The focus ring disappears on primary buttons. `accent-fg` #60a5fa against the `accent` fill #2563eb is 2.03:1. A ring drawn flush on a Publish or Save button is invisible (WCAG 2.4.13 / 1.4.11). Specify a 2px offset ring with a surface-coloured gap, or a two-tone ring (white inner, accent-fg outer). The ring must also stay distinguishable when the field already carries a danger, warning or presence outline. Today focus 'replaces' the outline in the state table, so a focused field in error loses its red edge.
- **UT-M4** Fixed bar and toasts obscure focus (WCAG 2.2 SC 2.4.11 Focus Not Obscured). A fixed 100px bar, plus toasts stacked above it on the right, will cover page content the admin tabs to or edits in place with CwaUiInlineText. That gets worse at 200% zoom on a 768px-tall tablet, where the bar is roughly a quarter of the screen. Require `scroll-padding-bottom: var(--spacing-manager)` on the scrolling root while the bar is open, and make 'Edit on page' and in-place editors scroll their target clear of the bar and toast stack.
- **UT-M5** Important information is only available on hover, which does not exist on a tablet. Touch users cannot reach the full value of a truncated status text or readonly IRI, the 'Still saving…' tooltip, or 'Hovering Use theirs shows their value in a tooltip'. reka-ui Tooltip does not open on tap. Worst case: a tablet editor resolves a conflict blind, without seeing 'their' value. Rule for the kit: a Tooltip may only duplicate something visible. Anything the admin needs (their value, error text, a long-wait explanation, the full IRI) goes behind a tappable CwaUiHint or popover. In the bar, the conflict control should open a small popover on tap showing 'Mia: <their value> / You: <yours>' with the two buttons.
- **UT-M6** Long wait is shown by colour alone (§4.2 'spinner turns warning', §7.2). On touch, the tooltip is the only text, so this breaks the brief's 'not colour alone' rule. Use a distinct glyph, such as a clock or a slowed spinner with a dot, plus tap-to-open text.
- **UT-M7** Touch target sizes are too small for tablet use. 24×24 is the WCAG 2.2 AA floor, not a tablet target. The ⓘ hint, chip ×, arrow buttons (24×32), conflict buttons (24px tall) and presence flags will be mis-tapped on an iPad, especially next to each other in a dense row. The flag lane also sits directly above the controls, inviting misses. Add a `@media (pointer: coarse)` size step: control 40–44px, hit areas ≥ 44px via padding or pseudo-element, and a correspondingly taller bar token. It stays constant across every tab, so R1 holds, but it is a different constant per pointer class. State in §2.3 that `--spacing-manager` is per pointer class and that the browser test covers both.
- **UT-M8** Bar heights in px break text-only zoom (WCAG 1.4.4). Safari's and Firefox's 'zoom text only', or a raised minimum font size (common with low vision), enlarge the 13px bar text inside a 32px control and 100px bar that do not grow, so labels and values clip. Express `--spacing-control`, `-manager-row`, `-manager-tabs` and the flag lane in rem so they scale with the font while staying identical across tabs. Also raise the bar base from 13px to at least 14px; 12px flags and badges are hard to read under a magnifier.
- **UT-M9** Fix the horizontal scroller on touch and for magnifier users (§4.6). (a) Arrows are opt-in (`arrows` prop) and hidden by default. On touch with iOS overlay scrollbars, the only cue is a mask fade, which also fades the controls at the edge below readable contrast. Make arrows always present when the row overflows on `pointer: coarse` or when the row can scroll, or show a persistent visible scrollbar track. (b) `aria-hidden` on focusable buttons is an ARIA violation: also set `tabindex=-1`, or better, keep them focusable with real labels ('Scroll fields right'), since switch-control and voice-control users cannot 'scroll by focusing'. (c) Drop the 'vertical wheel scrolls the row horizontally when … the page is not being scrolled' heuristic. It is unpredictable with trackpads and magnifier panning, and native Shift+wheel and horizontal swipe are enough. (d) A horizontal pan that starts on a text input must still scroll the row; test that iPad Safari does not start text selection or move the caret instead.
- **UT-M10** Nested horizontal scrollers are not usable on touch. A MultiSelect in the bar 'scrolls its chips within a fixed width' inside a row that itself scrolls, and swipes will scroll-chain unpredictably. In the bar, the trigger should always show the collapsed 'N selected' summary (or the first chip plus '+N'), with chips edited in the popover. Chips with × buttons belong only in modals and pages.
- **UT-M11** Small-screen behaviour for CwaUiDialog is unspecified (§4.7). It needs to say: (a) below about 640px or in landscape tablet height, dialogs go full-screen; (b) `columns: 2` collapses to 1 at narrow widths and at 200% zoom (WCAG 1.4.10 Reflow at 320 CSS px); (c) the sticky header and action bar must not take most of the space left when the iPad keyboard is open (size against `visualViewport`, and scroll the focused field above the keyboard); (d) date picker, select and hint popovers inside a dialog must stay inside the visual viewport and the focus trap; (e) whether the dialog covers the manager bar or sits above it. Also give floating labels a resting size of at least the 14px body text, and a floated size no smaller than 12px with fg-muted contrast. A magnifier user loses tiny floated labels, so consider `above` for modals too.
- **UT-M12** Error toasts without actions auto-dismiss after 10s (§7.1). A magnifier user zoomed into the bar's left side will never see a bottom-right toast in time. Make every error toast persistent until dismissed (WCAG 2.2.1), and pause all timers while the document is hidden. Also, when an error relates to the selected component, mark it on the bar as well (the tab badge or CTA), not only in the toast.

**Suggestions**
- **UT-S1** Add forced-colors support. Mask-image fades, dotted outlines drawn with box-shadow, and colour-only presence outlines vanish in Windows High Contrast or with inverted colours, which many magnifier users run. Use `outline` (not box-shadow) for focus and state, and add `@media (forced-colors: active)` rules so fades are turned off and state icons use system colours.
- **UT-S2** Disabled controls that carry a reason (a disabled 'Edit on page', disabled select options, the Group tab when full) should use `aria-disabled` and stay focusable and tappable, opening the hint. `disabled` removes them from the tab order, so the reason is unreachable by keyboard and invisible to touch. 50% opacity text also gives a magnifier user nothing to read.
- **UT-S3** Bump the focus-ring room inside the scroller. 4px inline padding just fits a 2px ring with a 2px offset, but not a ring plus the 2px-offset presence outline together. Use 6–8px, or draw the focus ring inset for controls in the bar.
- **UT-S4** Make the 'Edit on page' arrival visible. A 600ms, 1px accent flash is too faint at magnification and disappears under reduced motion. Leave a persistent 2px focus outline on the in-page editor until it blurs, and keep the 'Escape returns to the bar' behaviour.
- **UT-S5** For the tab strip on touch, give each tab at least 44px of hit width, keep the selected tab distinguishable by more than the accent fill (an underline plus weight), and give the error/conflict badge a text equivalent in the tab's accessible name ('Link, 1 conflict').
- **UT-S6** CwaUiInlineEdit (modal title) needs a visible pencil affordance and must enter edit mode on tap. 'Becomes an input on click/Enter' has no hover hint on touch, and the title currently looks like static text.
- **UT-S7** CwaUiNumber on touch should set `inputmode="decimal"` (or `numeric` when there is no fractional step). Stepper buttons need at least 44px on coarse pointers, with press-and-hold repeat that commits once on release, consistent with 'commits on step click'.
- **UT-S8** Tablet coverage in the browser tests. Add a 1024×768 and a 768×1024 coarse-pointer (`hasTouch`) project to the bar-height and 10-field scroll scenarios, and one 200%-zoom run, so R1 is proven where tablet editors actually work.
- **UT-S9** defineCwaConfig field declarations (§8.8) should not accept a `size` that overrides the coarse-pointer height. Generated tabs must inherit the same touch, contrast and focus rules as hand-written ones. Say so explicitly, so a config-only component cannot opt out of accessibility. Since `hint` moves into config, also keep hint text short and plain; plain text, not HTML, matches the Markdown COULD.

**Praise**
- **UT-P1** The always-reserved 16px status slot and the reserved flag lane are the right structural answer to 'state never shifts layout'. The draft also catches the real trap that overflow-x clips the presence flag vertically.
- **UT-P2** Making the surface decide the label (no labelPlacement prop) enforces R1 by structure rather than discipline, and requiring `label` even when it is visually hidden guarantees a programmatic name.
- **UT-P3** The hint opens on click or Enter, with its content wired through aria-describedby, rather than on hover. That is the right pattern for touch and screen readers, and it should be the model for everything still left in tooltips.
- **UT-P4** Using one polite live region per surface instead of one per field, and making error toasts assertive without taking focus, is correct and performant.
- **UT-P5** The 300ms grace before 'saving' and the 1.5s saved tick avoid flicker, and errors keep the value and offer an explicit Retry. That is exactly the optimistic, quiet feedback the brief asks for.
- **UT-P6** The reduced-motion handling is thoughtful: the spinner slows rather than stops, and the sweep becomes a static bar.
- **UT-P7** The uploader is explicitly not drop-only, has a focusable button, and announces two-phase progress for the downscale and upload steps.
