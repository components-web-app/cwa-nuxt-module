What the bar enforces
  • ResourceManager.vue wraps every tab in CwaUiManagerRow, so a tab cannot stack fields, and a CwaUiTextarea under the bar throws in dev.
  • Labels sit inline on the left. Secondary text goes in an ⓘ popover or the status slot.
  • The summary and the primary action are pinned at the end of the tab strip and never scroll away. Publish is not repeated inside the Publish tab.
  • Presence flags are portalled to a layer that follows the row's scroll, so the row needs no flag lane.
Where each tab comes from
  • Link: a site tab (24+ link tabs in CK and SR) on CwaUiLinkInput + CwaUiInlineHandoff.
  • Image: CwaUiImageAlt on the new upload binding (replaces CwaUiFormFile).
  • Ui: _tabs/component/Ui.vue. Style names come from defineCwaConfig; an unmatched class shows as "Unknown style".
  • Publish, Order, Info: Publish.vue, Order.vue, ResourceInfoTab.vue.

3 · Resource modals

Modals use the modal surface: floating labels, a helper or error line under the field, and 2.5rem controls. They are built on CwaUiDialog (reka Dialog), which replaces DialogBox, ModalInput, ModalSelect and ModalRadioTabs.

5 · Toasts and inline save feedback

Feedback is quiet when a save works and stays visible when it fails. A routine save is never toasted; it gets a tick in its slot. Toasts appear top right, under the admin header. Errors and toasts with actions stay until you dismiss them. Hover pauses the timer.

6 · defineCwaConfig: decided in #453

Agreed on #453 and being built in its own PR, outside this kit. The kit only reads the generated config: the Ui tab's style options and labels, and each layout's and page's description in the page settings selects.

<!-- app/cwa/components/Hero/Hero.vue -->
<script setup lang="ts">
defineCwaConfig({
  name: 'Hero',
  description: 'Full-width banner',
  instantAdd: true,
  defaultData: { title: 'New hero' },
  styles: {
    'black-bg': { label: 'Black Background', classes: 'bg-black text-white' },
  },
})
</script>
  • Components take name, description, instantAdd, defaultData and styles. Layouts and pages take name and styles. A ui/*.vue variant can declare its own styles. Manager tabs and UI variants stay discovered from the admin/ and ui/ folders.
  • cwa.resources, cwa.layouts and cwa.pages are removed from nuxt.config.ts, as is useCwaResource's styles option. cwa.pageData stays. No backward compatibility: the README has an upgrade section.
  • Static literals only: anything else is reported at build time, naming the file.
  • uiClassNames stores style:<key>. ResourceLoader resolves keys against the rendering SFC's styles during the server render, so pages arrive styled. A key the SFC doesn't know renders nothing and shows as "Unknown style".
