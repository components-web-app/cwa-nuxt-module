CWA Admin UI Kit Proposal v6 · #236 · UI kit only

The admin UI kit, v6

Every control is shown here in the state it will ship with. Only the kit is covered: how components declare their fields, styles and UI variants is a separate job. The menus, popovers, bar, modal and list all work, so try them with a mouse, a keyboard and a phone.

New in v6, after the v5 review panel:

  • The Routes tab is the Route, then three rows that open sub-views (section 6): Redirect to, Redirected from and Child routes, each with a one-line summary and ▸. A sub-view keeps the modal's tabs, with a stacked “‹ Routes” and title above its content; while a form is open its own Cancel and Save replace the footer, so only one Save is ever on screen and nothing opens on top. Back, Escape or another tab with something typed asks first.
  • Redirect to and Redirected from replace Forwarding and Redirects, and rows show the direction: /shaker → this page. “Not redirecting. Visitors to /kitchens/shaker see this page.” replaces the old “Off.” line, and no button ends in “…”.
  • Steppers keep to their range: type 9 into a 1 to 6 position and the field says “Between 1 and 6”; leave it or press Enter and it snaps to 6 and says so. − and + are disabled at the ends, with the reason.
  • Loading lists shimmer: one soft band sweeps across every skeleton row in step, and that is the only sign until “Still loading…” after about five seconds. With reduced motion there is no band, so a spinner and “Loading pages…” show at once instead.
  • Buttons have their own fill, lighter than a field's, with a semi-bold label, so an action never looks like an input.
  • ⋮ is the only “more” glyph: the bar, list rows, the tree and the phone modal header.
  • Design fixes: section actions sit on the heading's line without making it taller; the conflict diff is tint and weight only, and none when most of the value differs; alerts get a tinted surface and a coloured edge rather than the field tint; delete icons are grey until hovered; “Unsaved” is muted with a dot; phone list rows start their status at one place, Scheduled has a clock, and a date says what it is; the phone New status is a dashed ring, not a plus; the phone recommendation keeps “Use this” on its own line; phone toasts sit below a full-screen dialog's header.

From v5:

  • WCAG 2.2 AA. Darker field fills, 24px minimum targets, focus never hidden behind the bar, header or toasts, shapes as well as colours, one quiet live region per surface, and a checklist per component in the spec.
  • The Routes tab (section 6) with the kit's new tree for redirects and child routes. Route actions save at once; the modal's Save is only for the page's fields.
  • Search asks the API (section 2): first load, searching, slow, many results, no matches, offline and server errors, and a chosen page that isn't in the results.
  • A page's status in lists comes from its route: Live, Scheduled, Not live, Held back by parent, No route. Templates say what uses them. Row actions are Edit settings and Go to page.
  • Section headings read as headings: larger and heavier than labels, with a rule and more space above.
  • A conflict is a notice under its field, with both versions as plain quoted text and Use Mia's / Keep mine; a summary at the top says why Save is blocked.
  • Every ⓘ opens a popover, so nothing on the page moves.
  • Create buttons are “+ Page”, “+ Article”; a new component's action is “+ Draft” or “+ Add”. On a phone the bar's status is a glyph right next to Publish.
  • Toasts are tinted frosted glass (option B, chosen from three in section 8), and never move.

From v4:

  • No space is reserved for a status glyph. On a control with an end icon (a select's chevron, a date's calendar), the state takes the icon's place while it lasts: spinner, then tick, then the chevron again; error and conflict are a solid glyph button there. On a plain text input or stepper in the bar, the end padding widens only while a state shows, so the field's outer size never changes. Modal and page fields show no glyph inside at all.
  • Admin pages with forms use the modal's Save model: a local copy, a Save button, nothing saved as you type.
  • Unsaved changes are never lost silently. Cancel, ×, Escape and a click outside ask “Discard 3 unsaved changes?”; leaving an admin page or modal asks “Leave without saving?”; closing the browser tab gets the browser's own prompt. Nothing asks when nothing changed.
  • On touch screens every control's value is 1rem, so a select sits at the same size as the text input beside it.
  • Values are never clipped. A value that ends in an ellipsis is clipped sideways only, so ascenders and descenders show in full.

From v3:

  • Modals and pages edit a local copy and keep a Save button. Changed fields and tabs are marked, Save counts the changes and sends only those, errors from Save go on their fields, and a 412 asks per field which version to keep.
  • The page modal has tabs again (Details, Routes, Info, then page data tabs), including how they behave while creating.
  • The bar's status and primary action sit in the tab row on every tab, desktop and phone.
  • Only the innermost control under the pointer shows hover: stepper buttons, a chip's ×, clear buttons and status glyphs have their own shade, and the field's hover steps aside.
  • Textareas grow with their text up to 8 lines, with no resize handle.
  • Lists filter by type with square coloured toggles (Static blue, Dynamic yellow) and a matching dot per row; no more per-row thumbnails.
  • A failed save offers Retry and Reset. Undo is kept for things that happened.
  • A sliding tab indicator and calm micro-animations, all off under reduced motion.

Still true from v2:

  • Filled fields, no borders. A line appears only for focus (blue ring) or another editor (their colour).
  • Square everywhere. The toggle switch is the only rounded control.
  • Solid status glyphs: triangle, diamond and filled circles, each with a knocked-out mark.
  • One error pattern and one info pattern per surface. There are no hover tooltips on fields. Info opens in place in forms, so it never covers a field.
  • The link input is now the either/or group: choosing one option clears the others in the same save.
  • Friendlier spacing, a rebuilt modal form layout, a list on one grid, and phone layouts for all of them, with 44px touch targets.

2 · Select, multi-select and search menus

These follow the page theme. Open them with a click, a tap, or Arrow Down. Arrow keys move the highlight, typing jumps (select) or filters (search), Enter picks and Escape closes. When the window is narrower than 640px, menus open as a bottom sheet with the search pinned at the top, anything already typed carried into it, and the chosen styles shown as chips under the search. The sheet sits above the on-screen keyboard.

Page searches ask the API. The first open shows skeleton rows; typing waits 250 ms, keeps the previous results dimmed with a small spinner, and says “Still searching…” after 3 seconds. Each search cancels the one before it, a late answer is ignored, and closing the menu cancels the request in flight. Long lists say “Showing 20 of 143” with Show 20 more; there is no infinite scroll. Offline and server errors keep the previous results, with Retry. The Parent page's chosen value is not on the first page, so its label is fetched on its own. Focus stays in the search, and the result count is announced once the search settles, never per keystroke. Choose how the next searches answer, or type slow, offline or fail:

3 · Errors and info

Modals and pages show what Save returned: the message goes on the line below the field, linked with aria-describedby, and a conflict asks which version to keep. A client check (a bad URL) shows the same way before anything is sent. The bar has no room for a line, so the field's fill is tinted and its glyph is a button: click or tap it to open the message and its actions. Info is an opt-in ⓘ straight after the label. In a form it opens a note in place, under the label, and the field moves down so nothing is covered. In the bar it opens a popover titled with the field's name, with a close button. Use it only when a field's effect is not obvious from its label. Inline actions are text buttons with a 44px tap area; popovers and alerts use real buttons.

4 · The either/or field group

A resource that stores exactly one of several fields, such as a link that is a route or a rawPath. The segmented control only chooses which field is shown, and switching saves nothing. In the bar, committing a value saves it and clears the other options' fields in the same request, and Undo stays available until your next edit. In a modal the same change goes into the local copy, and Save sends it, with the clearing, in one request. CwaUiLinkInput is this group with Page and URL already set up.

5 · The manager bar

The bar is one row and never stacks. The row scrolls sideways with fades at its edges; with a mouse, arrows also appear at a hovered edge, and they hide while a field has focus. Focusing a field scrolls it fully into view, label included. The status and the primary action are pinned in the tab row, top right, on every tab; they never move into the field row. The primary action is a split button: its arrow (“More actions”) opens the component's other actions, as today's admin does. Switch between an existing component, one in a full group, and a new one below to see its options. Type in Title to see it save. Description is edited on the page: its button scrolls to the text and focuses it. Mia's flag sits in a layer above the bar, on the field's top edge, so it never covers the tabs and the bar's height never changes. When you type in a field Mia is in, the flag stays up and reads “Mia is editing this too”.

Writing a tab

A manager tab's single root is CwaUiManagerTab, which is the one-row layout. Fields are its direct children and lay themselves out for the bar: inline label, bar control size, the state in the end icon's place, errors as a popover. Kit inputs take field="…" and build their model from the tab's resource; :model stays for page data, a custom debounce and other unusual cases. A tab whose root is anything else gets a development warning.

<CwaUiManagerTab>
  <CwaUiInput field="label" label="Label" />
  <CwaUiLinkInput :fields="['route', 'rawPath']" label="Link" />
  <CwaUiToggle field="openInNewTab" label="Open in a new tab" />
</CwaUiManagerTab>

On a phone

The same bar with 2.75rem controls and no arrows. The status stays in the tab row as a glyph only, right against Publish with no gap, so the tabs get more room; each state has its own shape (a dot for Draft, a clock for Scheduled, a dashed ring for New, the spinner, the tick, the triangle, the diamond; a plus only ever means create), and its name is read out. Fields are sized so the next one peeks in, and the row snaps to fields.

6 · Modals and admin pages

A modal edits a local copy and keeps a Save button. Nothing is sent as you type. A changed field says “Unsaved” after its label (nothing is drawn inside the field), its tab shows a dot, and Save counts the changes. Cancel, ×, Escape or a click outside with unsaved changes asks “Discard 3 unsaved changes?” first; with nothing changed it just closes. Save sends only the changed fields, in one request per resource. Errors returned by Save go on their fields, linked below them, and each tab holding one gets the triangle and is opened. If someone else saved first (a 412), nothing is saved and each field you both changed asks which version to keep. Creating uses the same button and the same flow.

Layout: a label, 0.375rem, the field, 0.5rem, the helper line; fields 1.5rem apart; sections 2.5rem apart with space and no rules. The header, the tabs and the footer stay put while the body scrolls. Below 640px the dialog fills the screen, Delete moves to the header's ⋮ menu, and Cancel and Save share the footer row.

The Routes tab

The tab shows the Route (path, status, recommendation and Edit route), then three rows that open sub-views, like a phone's settings: Redirect to (“Off” or “→ /kitchens/shaker-range”), Redirected from (“3 old addresses”) and Child routes (“2 routes”). A sub-view is a page of the Routes tab: the tab strip stays, with Routes selected, and only the tab's content changes, under a stacked header (“‹ Routes”, then the sub-view's title, which takes focus). Edit route, Use this, Redirect to another page, Change and + Add open a form there, and while a form is open its own Cancel and Save replace the modal's footer, so only one Save is ever on screen. What saving will do is said above the buttons, so Save route is the confirmation and nothing opens on top; only deleting and removing ask again. Back, Cancel, Escape or another tab with something typed asks “Discard your route changes?”; with nothing typed they go at once, and coming back to Routes shows its main view. Focus returns to the row or button that opened the sub-view. No browser history is added, and the tab's hidden main view is inert (the tab strip is not). The modal's Save is only for the page's fields. Redirected from and child routes are trees: click a row, then use the arrow keys (Right opens a row or moves to its button, Left closes it or goes to its parent; Delete removes an old address).

Admin pages: the same Save model

A /_cwa page with a form (here, site settings) works like a modal: it edits a local copy, nothing is sent as you type, and Save counts and sends the changes in one request. Change a field, then click Pages, Layouts or Users: leaving with unsaved changes asks first (in the module this is the existing NavigationGuard). Cancel asks too. Closing or reloading the browser tab with unsaved changes gets the browser's own prompt, whose wording we cannot change. When nothing has changed, nothing asks.

7 · Lists

Every list uses one grid, and the header row uses the same columns, so badges, dates and actions line up down the page. The whole row is the link. Rows are 4rem tall when they have two lines. There are no per-row thumbnails: a small dot after the name gives the page's type, Static (blue) or Dynamic (yellow), and the toggles above the list filter by it. A toggle is a square filled button with its colour as a dot when off, and filled in that colour with a check when on; none on shows every type. Below 768px a row becomes title and ⋮, with the status first on the second line (a dot, a clock for Scheduled, a hollow square for a template, always in the same place), then “edited 15 Nov” unless the status already carries a date, and the path last, so only the path is cut. Loading: skeleton rows at the real row height with one shimmering band, and nothing else until “Still loading…” after about five seconds. With reduced motion the band is off, so a spinner and “Loading pages…” sit above the rows from the start. Use the buttons below to hold the loading state. A template's count (“Template · 14 pages”, or “Template · unused”) needs api-components-bundle#587; until it ships the row says “Template”. On a phone the toggles and sort share one scrolling row, and row actions open as a bottom sheet. Search, the filters and the checkboxes work.

8 · Toasts and inline save feedback

A routine save is shown in the field, never in a toast. Toasts are for things that happened away from a field: a background failure, a field in error that was unmounted, an undo. A failed save offers Retry and Reset (Retry all and Reset all for several), never Undo. Success and info toasts go after 4 seconds, warnings after 6; errors and toasts with actions stay until dismissed. On a phone toasts sit at the top, so they never cover the bar.

The v5 questions are settled: the palette additions and the treegrid are approved, and route edits use the sub-view. Buttons have their own fill, ⋮ is the only “more” glyph, updateResource keeps its return, and the screen-reader pass runs once per new component and before each release.
